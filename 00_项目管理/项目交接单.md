## 三、本轮踩到的坑（细节在 `docs/开发上下文.md` §5.1br–§5.1bx 与坑表）

1. **代理 + DNS 双坑**（本轮最难缠的一个）：全局 `http.proxy` → `127.0.0.1:7993`（代理软件没开）⇒ 所有 git 远端操作失败；绕过后 DNS 对 `github.com` **轮换返回多个真实 IP**（`20.6.7.17` / `20.247.166.64` / `140.82.112.3` …）且**同一 IP 的可达性也随时间翻转** ⇒ 「记一个可用 IP」不成立。**正确做法**：临用前 `curl.exe --resolve github.com:443:<IP> -o NUL -w "%{http_code}" https://github.com/` 探（200 才算通）→ 拿到 200 **立刻**用 `git -c http.curloptResolve=github.com:443:<IP>` 推 → 失败就换 IP / 隔 15–20 秒重来。
   ⚠️ **别用 git 的失败反推 IP 不可用**（git 报的是 TCP 握手超时，curl 走同一个 IP 却能成功）。
2. **中文 Markdown 的 `**粗体**` 会静默失效**：CommonMark 的 flanking 规则 —— **收尾的 `**` 紧前面是标点、紧接着后面是汉字** ⇒ 不解析成强调、星号原样显示（**与括号全角/半角无关**）。⇒ 发布正文出现过字面量星号。**判据用 GitHub 自己的 `POST /markdown` 渲染端点验**（纯渲染、无副作用）—— 靠记忆推 flanking 规则**会推反**（我第一次把「开」配对的 `**` 也算成失效，误报 1144 处）。
3. **发布正文必须独立复核** —— `release_publish.py` 只验「**资产**字节一致」，**不验正文渲染** ⇒ 脚本打印「✅ 发布完成」≠ 正文好看。
4. **游戏目录被临时改动 ⇒ 干净环境测试红 4 条**（计数 +1：`376 != 375` / `98 != 97` / `122 != 121`）—— 是用户另一个项目在改游戏目录，与修改器代码无关。**排查看「目录」mtime，不是文件 mtime**（加/删文件会更新目录 mtime，哪怕文件自身时间戳是旧的）。
5. **搬 L2 整页模板里的块 ⇒ i18n 词表要搬**（键**和**值都要）—— 英文界面渲染的是词表那份；只改 `index.html` 的话中文挪了、英文还在原地。
6. **静态断言 + 真点巡检要对称，且必须实测能红**；**反证要精确到目标维度** —— 整体退回改前状态时，断言可能红在别的分支上（U188：整体退回后巡检红在「`#ruinsbox` 不存在」，而那个 `id` **本身也是同一次改动新加的** ⇒ 只证明了「元素缺失会红」，没证明要验的「位置判断」有效 ⇒ 补做了「只回退位置、保留 id」的第二轮反证）。
7. **校验「块的位置」别拿块的标题位置比** —— 路线图**标题**永远在 `{12}` 之前 ⇒ 要比**路线图块的收尾**（`{2}\n      </div>`）。
8. **`git commit -m` 里带反引号会被 PowerShell 吃掉** ⇒ 写到文件再 `git commit -F <文件>`（本轮踩了两次）。
9. **`rm --` 必须单独一条命令、只含字面量目标**；`Remove-Item` 被本地安全策略拒。
