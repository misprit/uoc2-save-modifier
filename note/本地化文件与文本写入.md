# 本地化文件与文本写入

适用命令：`brief`、`full`、`troopName`；参考列表生成也依赖同一套翻译数据。

本项目存在**两套**本地化文件：读取用的游戏包文本，以及写入用的存档专属
temp mod 文本。两者位置不同，不要混用。

## 读取：翻译从哪里来

数据源：`<原版包>/<包名>/localization/<locale>/strings.yml`，同目录下的
`ui.yml` 若存在也一并读取作为补充。

实现：`src/save_modifier/translations.py` 的 `TranslationStore`。

- 构造参数为 `config.orig_packages` 与 `config.locale`（默认 `chi`）。
- 按包名自然序遍历（`dlc2` 先于 `dlc10`），后加载的包覆盖先加载的同名键。
- 只收字符串类型的值，`null` 或其它类型会被忽略。

该翻译用于把文本 id 解析成中文，例如单位/总部的 `name_brief`、`name_full`，
卡牌的 `title`、`subtitle`、`description`。参考列表里翻译缺失时回退显示原始
id；卡牌参考中字段本身为空则显示 `—`。

## 写入：自定义文本写到哪里

目标文件：`<temp_mod>/localization/<locale>/<存档名>_strings.yml`。

其中 `<temp_mod>` = `<uoc2_appdata>/_packages/<存档名>_temp`，由
`config.temp_mod_dir_for(存档名)` 给出。每个存档一个文件，互不影响。

实现：`src/save_modifier/localize.py`。

| 函数 | 作用 |
| --- | --- |
| `set_localization_text` | 向上述文件写入一个 `{文本id: 文本}` 键值 |
| `localize_entity_text` | 把实体的 `name_brief`/`name_full` 指向默认 id 并写入翻译 |
| `localize_unit_name_brief` | `troopName`：单位名改为 `<原 name_brief>_custom` 并写入 |

文本 id 约定：实体默认 id 为 `id_<实体名>_<brief|full>`；`troopName` 使用
`<原 name_brief>_custom`，只影响该单位，不改实体。

写入属于“自定义实体”通道：需要重启游戏（重载 mod）才能看到效果，与数值修改
要先 `save` 回 `.usg` 的机制不同。

## 覆盖原版文本

把同名键写进 `<存档名>_strings.yml` 即可。游戏加载 mod 时，该文件晚于原版包
读取，因此会覆盖原版同 id 的文本。注意这只影响显示，不改动包内文件。

## 常见问题

- 游戏里仍显示 `id_xxx`：该 id 不在任何包的 `strings.yml` 中，或
  `config.locale` 与实际语言不符。
- 改了名字但游戏内没变：确认写入的是 temp mod 的 `localization`，不是存档
  工作目录；并确认已重启游戏。
- 卡牌参考里标题是英文 id：说明该 id 缺中文翻译，参考列表已回退显示 id。
