# 实体文件布局与包搜索

适用命令：`create-type`、`create-spec`、`bind`、`rename`。

## 一个实体由哪些文件构成

unit（三件套，缺一不可）：

| 文件 | 作用 |
| --- | --- |
| `data/entity_types/unit_types/<名>.yml` | 类型数值（attack、name_brief 等） |
| `assets/surfaces/unit/<名>/` | 贴图目录 |
| `assets/models/<名>_meta.yml` | 模型 meta，定义三维模型从哪里取 |

specialist（两件套）：type yml + surfaces 目录，没有 meta。

## 搜索顺序

搜索根依次为：

1. `config.mod_search_paths` 中实际存在的目录；
2. `<原版包>/<战役包>`；
3. `<原版包>/base`。

战役→包映射硬编码在 `package_map.py`（`france`/`tutorial`/`west` → `base`，
`blitzkrieg` → `dlc1` …），表外一律回退 `base`。

type、surfaces、meta **各自独立**按上述顺序取第一个存在的候选，因此三者可能
来自不同包（例如 type 在 base、meta 在 dlc）。

## 模型 meta 的来源：`--model-from`

三维模型体积大、只随 DLC 分发，而 meta 决定模型路径，所以 meta 需要能单独指定：

```
create-type <原型> [新名] --model-from <包名|路径>
```

- 包名：`<原版包>/<包名>/assets/models/<原型>_meta.yml`
- 目录：`<目录>/assets/models/<原型>_meta.yml`
- 文件：直接作为 meta
- 显式指定但找不到：创建失败，不回落默认搜索

未指定时 meta 沿用上节顺序（战役包优先）。

## 写回位置

克隆结果写入 `%LOCALAPPDATA%/.uoc2/_packages/<存档名>_temp/`，按新名重新组织
三件套；meta 仅在内容非空时写出。**模型本体不复制**，游戏仍须能加载来源包
（通常即已安装的 DLC）。创建后需重启游戏重载 mod。
