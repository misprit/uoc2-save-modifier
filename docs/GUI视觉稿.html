3 · 特种兵挂载规则（已并入单位页）

特种兵页已取消 —— 挂载 / 卸下是「某个单位的事」，跟单位放在一起才对。 这一段不再是功能页，只把游戏自己的挂载规矩写清楚（GUI 的备选区要照它过滤）。

游戏的判定（字节码 unit.pyc::UnitState._can_add_specialist_no_len）：
  1. 阵营必须相同 —— 单位的 type.faction = 特种兵的 faction；
  2. 国籍必须相同；或者单位的国籍有「父国籍」且父国籍 = 特种兵的国籍 （例：italian.parent_nationality = german ⇒ 德军单位可挂意大利特种兵）；
  3. captured=True（被俘获的牌）跳过上面两条。
容量另算：len(specs) < max_spec， 而 max_spec = min(3, 类型表的 max_spec)（实测分布：1×233 / 2×314 / 3×80）。
备选池的口径：默认只列「本战役有的」（2026-11-18 用户拍板）
  1. 战役默认池 = 该战役所有战线 × 所有会议的商店 spec: 条目 ∪ 该战役场景 units.yml 里游戏自己挂过的 specs[].type；
    实测每个战役的商店只卖玩家一方阵营（allies / axis / soviet 各自纯净）， 且年代自洽（blitzkrieg 只有 _39/_40/_42，desert 只有 _42）;
  2. 最终候选 = 战役默认池 ∩ 上面那条游戏规则（阵营 + 国籍）;
  3. 兜底：找不到战役包 / 某个单位交集为空 ⇒ 放宽成「仅规则」并标注原因。

⚠ 只用商店是不够的 —— 商店会漏掉 113 种游戏自己在该战役场景里挂过的特种兵 （us_spec_42 / ff_recon_42 / ger_at_40 …）； 加上场景集合后漏 0 种（e163 实测）。
⚠ 不能靠名字后缀判年代 —— DLC 战役用 _dlcN 命名（ger_at_dlc10）， 18~41 个条目根本没有年份。
「显示全部 375 种」之后：按国籍分一层（2026-11-18 · U11）
  1. 阵营分隔带（同盟 / 苏联 / 轴心）—— 当前单位所属的阵营排最前；
  2. 每个国籍一组：组头 = 国籍中文名 + 种数 + 「可挂 N」徽章，点组头折叠 / 展开；
  3. 组内按中文名排序；组之间按「可挂数 → 种数」排（可挂的排前面）；
  4. 默认视图（战役池）不分组 —— 本来就只有 9 种。

⚠ 同名国籍：苏联 / 意大利 / 波兰 / 罗马尼亚 / 瑞士 / 南斯拉夫 各有两个 id （本国阵营 + 参战国版本）⇒ 靠阵营分隔带区分，不另加括号后缀。
⚠ 国籍中文名走 locale id_<nat>_name_brief；实测游戏自己的 croatian 键是错的（id_croatian_brief 在中文表里译成了「匈牙利」， 正确键是 id_croatian_name_brief → 克罗地亚）—— 375 种里没有克罗地亚的，但这个坑要知道。

4 · 总部页（技能矩阵 / 兵库）

总部在存档里有两棵不同的树：分支等级 = branch_levels （五个分支各一个等级，决定解锁到哪一级），技能树 = branches （每个总部自己的技能清单，249 个总部 / 4818 条技能实测）。
本页照游戏内的升级面板重做：行 = 分支、列 = 级别 1/2/3，格子里是技能图标 —— 右下角数字 = 该技能 CP 消耗，右上角小点 = 专精槽位（金色实心 = 已专精）。 图标、徽章全部取游戏原贴图（surfaces/hq_upgrade/，140×140，20 个动作全覆盖）。
