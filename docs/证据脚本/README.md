# 证据脚本

这些是写《开发规范与Prompt.md》时用来**取证**的脚本 —— 规范里每一条
"实测结论"都能用它们重新跑一遍复核。

## 怎么用

```powershell
# 终检：检查规范文档自身的结构（锚点、表格、编号连续性、坏字符）
python 证据脚本\v6_check.py
python 证据脚本\v11_verify.py

# 单个取证脚本，直接跑（大部分是 python <脚本名>）
python 证据脚本\e126_unicode.py
```

## 目录里有什么

| 前缀 | 内容 |
|---|---|
| `a*` `b*` `c*` `d*` | 早期普查：容器结构、字段集、状态分类、覆盖盲区 |
| `e*` | 逐条取证：字段/字节码/存档普查（§12 表格逐条对应） |
| `v6_check` / `v11_verify` | 规范文档自身的终检 |

## ⚠️ 两条注意事项

1. **脚本里有本机绝对路径**（游戏安装目录、`D:\MiniMax\_analysis` 等）。
   它们是"取证现场"，**故意没改** —— 改了就不再是当时的证据。
   在别的机器上跑要先改路径。
2. 部分脚本会**读玩家的真实存档**（只读），部分会写临时目录。
   都在 `%LOCALAPPDATA%\.uoc2\save` 下只读，不会改存档。

## 与规范文档的对应关系

`../开发规范与Prompt.md` 的 **§12「证据与复现」** 表格逐条列出了每个脚本
负责证明哪一条结论；§10 的坑清单里带 `e1xx` 编号的条目也对应这里的脚本。
