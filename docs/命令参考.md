# 命令参考 —— 自测入口

> 这里的命令属于**自测入口**（`src/save_modifier/repl.py`），是核心库
> `save_modifier_core` 的命令行外壳，**不是产品界面**。
> 玩家用的是 GUI；这里给的是开发/排查问题时直接敲命令的通道。
>
> 核心库的正式接口见《[核心库调用说明](核心库调用说明.md)》。

`<参数>` 必填，尖括号只是占位，输入时不要带尖括号。
`[参数]` 可选。

---

## 修改是怎样生效的

1. **存档 `.usg` 是一层 ZIP**（根目录是 5 张 L1 表 + 检查点 + 战斗层 + 文档）。
   核心库直接读它，**不解包到工作目录**。
2. **编辑先规划，再写回。** 所有改动命令只生成**计划**（`plan_edit`），
   **一个字节都不碰磁盘**；`plan` 看 diff、`commit` 才真正写。
3. **写回是四步**（顺序固定）：备份 → 写临时文件 → 校验 → 原子替换。
   备份叫 `<存档名>_BACKUP.usg`（同名已存在就 `_BACKUP_2`…，**绝不覆盖**）。
4. **撤销是修改器自己的**：`undo` 撤销上一次 `commit`（粒度 = 一次 commit）。
   它与游戏内的「重置会议」是**两套独立**的机制，谁先谁后都可以。
   撤销前会**校验基准** —— 存档在你改完之后又被动过的话，**拒绝撤销**并说明原因。
5. 写回后要**重新读档**才能在游戏里看到变化。

## 存档

### `saves`

列出本机的存档（只列 `is_primary` 的 —— 备份与副本不列）。

```text
存档根目录: C:\Users\...\AppData\Local\.uoc2\save

  1. Stalingrad（战役 · stalingrad）  [战役]  campaigns/Stalingrad.usg
  2. avalanche（独立场景 · avalanche）  [场景]  games/west_avalanche.usg
```

### `open <序号|save_id>`

打开存档。序号是 `saves` 里列的序号；也可以直接给 `save_id`
（`campaigns/Stalingrad.usg`）或存档名。

### `view`

当前存档的概览：阶段、声望/分数、能力位、各表条目数、注意事项。

### `caps`

只打印能力位（8 个）。GUI 的启用/禁用就是按它来的。

### `units [关键字]` / `hqs` / `cards` / `store`

列出单位 / 总部 / 卡牌（根表 + 手里）/ 商店。

`units` 支持关键字过滤（id、type、中文名都能匹配），并显示
`xp`、战力（`act/sup`，有类型上限时写成 `act=7 sup=0/7`）、已挂的特种兵。

> 中文名来自游戏原版的本地化表（只读）。

### `types [unit|spec|card|hq]`

列出类型目录里的候选值（单位 627 / 特种 375 / 卡牌 39 / 总部 213）。
**只是候选，不是白名单**。

## 编辑

所有编辑命令都只生成计划，不写盘。

| 命令 | 说明 |
|---|---|
| `xp <单位id> <值>` | 经验值 0..400 |
| `st <单位id> <活跃> [压制]` | 战力 `act_st` / `sup_st` |
| `name <单位id> <明文>` | 改显示名 —— **直接写明文**，不写 temp mod、不写本地化包 |
| `spec <单位id> <特种类型>` | 加特种（类型必须在 375 个 specialists 里） |
| `unspec <单位id> <类型> [idx]` | 卸特种（同名多条时用 `idx` 指定卸哪一条） |
| `supspec <单位id> <类型> <0\|1> [idx]` | 特种兵的**压制 / 恢复**（0=被压制，1=活跃）|
| `pool <总部id> <条目序号> <数量>` | 总部兵库某条的存量 |
| `ptg <值>` | 声望 |
| `score <值>` | 分数 |
| `card add <卡牌类型> [槽位]` | 加卡（省略槽位取第一个空槽） |
| `card del <槽位>` | 删卡 |
| `store set <战线> <序号> <price\|quantity> <值> [store\|elite_store]` | 改商店条目（子商店可省，默认普通商店）|
| `store del <战线> <序号> [store\|elite_store]` | 下架商店条目（**删条目**，不是把 quantity 设 0；子商店可省）|
| `hand` | 恢复上次会议的牌局（读 L2 检查点 → 写 L1） |
| `asset <资产名> <可用次数> [总次数] [每回合]` | 战区资产（**只在当前进行中的战斗里有效**）。省略「总次数」= 无限；省略「每回合」= 1（游戏要求 ≥ 1）|

战区资产的简写：`air` `airArt` `airRec` `pb` `supply` `ss` `nb`。

**不支持**（会明确报错，不会静默忽略）：

* `type`（改单位编制）
* 新增单位 / 新增单位类型
* 改登陆进场特种兵
* 跳到某会议
* 改 `milestones`

## 写回

### `plan`

显示上一次编辑的 diff 与校验结果。

```text
将修改 1 个文件（units.yml），1 条提醒
  · 单位 1 的 xp：314 → 77

--- units.yml（L1）---
--- units.yml（改前）
+++ units.yml（改后）
@@ -17,5 +17,5 @@
   type: ger_jag_dlc4
   uv: [354, 215]
-  xp: 314
+  xp: 77

校验: 可提交（1 条提醒）
  ⚠️ 登陆单位被补兵后 XP 会被重算掉一部分（§3.5.6）
```

> diff 只会出现**真正改动的那几行** —— 核心库的 YAML 序列化器复刻了游戏自己的
> 规则（字节码实证），所以没动的行一个字节都不变。

### `commit`

写回。备份 → 校验 → 原子替换，成功后压撤销栈。

```text
已写入 s.usg（改动 1 个文件）
备份: s_BACKUP.usg
撤销: undo
```

### `undo`

撤销上一次提交。

```text
已撤销 1 个文件的修改
```

基准过期时：

```text
❌ 撤销基准已过期，拒绝执行：存档在你改完之后又被动过（可能是在游戏里手动改的）
  units.yml：内容与我改完时对不上（现在 a1b2c3…，记录 4d5e6f…）
  ⚠️ 提示：可以把 bak 文件夹里的 `_BACKUP.usg` 复制回去作为回退
```

### `stack`

看撤销栈（栈顶在最后一行）。

```text
撤销栈: ...\campaigns\s.undo.json（1 条）
  1. 2026-11-17T23:26:48  改了 1 个文件：单位 1 的 xp：314 → 77  [units.yml] ← 栈顶
```

## 其他

### `selftest`

跑一遍核心库自检：路径探测、类型表条数、存档数与各存档的能力位。

也可用 `python -m save_modifier.main --check` 只跑这一段。

### `refs`

从存档的 `document/` 生成名册参考表（单位 / 总部，带中文名）到临时目录，
并打印路径。

### `paths`

打印探测到的游戏目录、存档目录、用户包目录与各包。

### `exit`

退出。

## 与旧版 REPL 的差别

旧版 REPL 里这些东西**已经砍掉**了，原因见《UOC2存档修改器-开发规范与Prompt.md》§7.5：

| 砍掉的 | 为什么 |
|---|---|
| `create-type` / `create-spec` | 新建单位/特种类型要写游戏包，跨存档共享，**游戏内回退不掉** |
| `bind` / `bindInfo` / `reu` | 类型绑定写的是 temp mod，不是存档 |
| `rename` | 改名**直接写明文**（⚠️ U148：**两份表都写** —— 根表 + `document/` 名册，否则战役地图上看不到） |
| `troopName` / `brief` / `full` | 本地化写入 —— 不写 temp mod、不写本地化包 |
| `qs` / `ql` | 快速存读档 —— 产品决策：**不做**频繁存读档 |
| `type <id> <类型>` | 改编制 —— 硬约束不做 |
| 配置向导 | 核心库自己会探测路径（读 Steam 注册表 + 常见安装位置） |
