# 命令参考

`<参数>` 必填，写作尖括号只是占位，输入时不要带尖括号
`[参数]` 可选，可省略

- **存档名**：`.usg` 文件名去掉扩展名。如 `blitzkrieg.usg` 的存档名是 `blitzkrieg`。
- **单位 id**：unit id，unit即登场的部队，可用 `find` 或参考列表查到。
- **数据目录**：默认 `%LOCALAPPDATA%/.uoc2`，可在配置文件里改。存档、临时 mod、工具状态都在这下面。

---

## 修改是怎样生效的

1. **存档 .usg 是压缩包。** 工具打开存档时把它解包到 `<状态目录>/<存档名>/work/`（状态目录默认是启动脚本旁的 `data/`，可由 `config.yml` 的 `state_dir` 改到游戏数据目录或自定义路径），之后所有读取和修改都发生在这个"工作目录"里。
2. **数值类修改先留在工作目录。** 声望、单位、战区资产、卡牌、类型绑定，都要执行 `save` 才会打包回 `.usg`；再在游戏内重新读档才能看到变化。
3. **自定义实体与文本走另一条通道。** `create-type`、`create-spec` 建出的新类型，以及 `brief`、`full`、`troopName` 写入的中文文本，都写在 `<数据目录>/_packages/<存档名>_temp/` 下，作为临时 mod 被游戏加载。这类改动需要**重启游戏**（重新加载 mod）才生效，`save` 管不到它们。
4. **`save` 是整体覆盖。** 它把工作目录的全部内容打包覆盖到 `.usg`。如果这期间游戏又保存过该存档，游戏的新进度会被这次覆盖冲掉。改之前先 `qs` 备份一次，是最省事的保险。

另外两件工具自动做的事：

- 进入某个存档时，若参考列表目录还不存在，会依据存档的战役剧本生成单位与总部列表；卡牌列表缺失时也会补上。
- 进入存档、执行 `re` 或 `ql` 之后，会把绑定文件里登记的单位类型重新应用到当前单位（战役阶段推进时，游戏会用段脚本把单位类型覆写回默认值）。

---

## 存档命令

### `open [存档名]`

切换或重新打开存档。

- **不带参数**：列出所有"主存档"（战役与独立场景合并，按修改时间从新到旧），每行标注类型：

  ```text
  可用的存档：
    1. blitzkrieg2  (战役存档)
    2. blitzkrieg_low_countries  (场景存档)
  ```

  输入序号或完整文件名均可。也可以输入名称（不带 `.usg`）。

- **带参数**：先在列表中精确匹配名称；找不到时，再到 `save/campaigns` 与 `save/games` 下直接寻找 `<名称>.usg`。因此**备份档虽然不出现在列表里，仍可以用完整名称打开**。两处都找不到时打印 `未找到存档 <名>`。

打开成功后：

1. 解包到 `<状态目录>/<存档名>/work/`（旧工作目录被清空重建）；
2. 把存档名写入 `last_save.txt`；
3. 首次生成参考列表；重新应用部队类型绑定；

"主存档"的判定规则：
- 战役目录 `save/campaigns` 下，文件名不含 `_` 和 `-` 的才算主存档，带编号或后缀的视为备份；
- 独立场景目录 `save/games` 下，游戏本身就用 `<战役>_<场景>` 命名，所以带下划线是常态，只排除以 `_quick`、`_backup` 结尾的备份。

### `save`（别名 `s`）

把工作目录整体打包，覆盖原 `.usg`，打印 `已保存到: <文件名>`。

- 数值类修改到此才真正落盘；之后在游戏里重新读档即可看到。
- 自定义实体和本地化文本不在存档内，`save` 不会打包它们，也不需要重新保存。

### `qs [后缀]`

把当前存档的 `.usg` 复制一份作为备份，默认后缀 `_quick`。

- 后缀会自动补下划线：`qs bak` 与 `qs _bak` 都得到 `<存档名>_bak.usg`。
- 备份文件与主存档在同一目录。

### `ql [后缀]`

用同名备份覆盖主存档，随后重新解包并重新应用绑定。
- 默认用 `_quick` 备份，规则与 `qs` 相同。

### `re`

重新从磁盘上的 `.usg` 解包，丢弃工作目录里未保存的修改，再重新读取单位列表并应用绑定
适用两种情形：游戏侧更新了存档，需要重新读入；或改乱之后想回到存档的原始状态。

### `exit`

退出修改器（`quit` 等效）。
未 `save` 的修改会留在工作目录，但下次打开该存档时工作目录会被重新解包覆盖，所以效果等同于放弃这些修改。

## 声望与战区资产

### `ptg <数量>`

设置战役或场景的声望（prestige）。

| 写法 | 效果 |
| --- | --- |
| `ptg 200` | 直接设为 200 |
| `ptg +50` | 在当前值上加 50 |
| `ptg -30` | 在当前值上减 30 |

- 写入存档根目录 `main.yml` 的 `prestige`

### `st <代码> <to_use,total,turn>`

设置某项战区资产（空袭、空中补给、炮舰轰炸之类）在当前战斗中的可用次数。

```text
st air 3,0,3
```

第二个参数是三个用逗号分隔的整数，**逗号之间不要加空格**（加了空格会被当成多个参数，导致解析失败）。

| 位置 | 含义 |
| --- | --- |
| 第 1 个 | `to_use`：当前可用的次数 |
| 第 2 个 | `total`：整场战斗的总次数上限；写 `0` 表示不限（存档内记为 `null`） |
| 第 3 个 | `turn`：每回合的可用次数 |

通常把第 1 个和第 3 个写成同一个数，表示"本回合立即可用，之后每回合恢复到这个数"，总次数写 0 不限。
资产代码与存档内的对应名称：

| 代码 | 存档内名称 | 资产 |
| --- | --- | --- |
| `air` | `air_attack` | 空袭 |
| `airArt` | `flying_artillery` | 空中炮击（飞行炮兵） |
| `airRec` | `long_range_recon` | 空中侦察（远程侦察） |
| `pb` | `precision_bombing` | 精准轰炸 |
| `supply` | `air_supply` | 空中补给 |
| `ss` | `saturation_strike` | 饱和打击 |
| `nb` | `naval_bombardment` | 炮舰轰炸 |

写入位置是**当前战斗**的运行时文件：

- 战役存档：`games/<当前场景>/main.yml`
- 独立场景存档：根级 `game/main.yml`

具体落在该文件的 `theater_assets` 第一组里。同一资产已存在时整条替换，不存在则追加一条新记录。

## 卡牌（仅战役存档）

卡牌命令只适用于 `save/campaigns` 下的战役存档。独立场景存档没有 `cards.yml`，执行时会提示：

```text
错误: 卡牌命令仅适用于战役存档（独立场景存档没有 cards.yml）。
```

### 共同规则

- **槽位编号 1–5。** 游戏实际卡槽数随难度变化，工具无法从存档判断真实数量，只做 1–5 的宽松校验。
- **卡牌类型名**来自包数据，是 `data/entity_types/cards/<名>.yml` 的文件名主干。用 `refs` 打开"卡牌列表"文件夹，可以按阵营查到每张卡的中文标题、说明与类型名。
- **新写入的卡固定为**：`is_free: false`（按非免费卡处理）、`used: false`、`unit_id: null`、`position: <槽位>`。

### `cardList`

列出当前持有的卡牌与槽位占用情况。辅助命令，在游戏内直接查看会快得多。

```text
当前卡牌（2 张）：
  槽位 1: 轴心卡车（truck_axis）
  槽位 3: 空中补给（air_supply_axis）（已使用）
空槽位（宽松范围 1–5，实际槽位数随难度）：2、4、5
```

### `cardAdd <卡牌类型> [位置]`

直接往卡槽里放一张卡，**不扣声望**。

- 省略位置时，取 1–5 中第一个空槽；没有空槽时提示先指定位置或删除一张卡。
- 指定位置已被占用时，打印 `覆盖槽位 N 上的卡牌 <旧类型>。` 然后覆盖——**旧卡直接消失，不会退回声望**。
- 若卡牌的阵营与当前战役扮演的阵营不符，会要求二次确认：

示例：
```text
> cardAdd truck_axis 2
已添加卡牌 轴心卡车（truck_axis） 到槽位 2。
```

### `cardBuy <卡牌类型> [位置]`

与 `cardAdd` 相同的放置规则，但按"购买"处理：添加的同时扣除卡牌费用。

- 目标位置已有卡时**拒绝**
- 必须能在包中找到该卡牌定义并读到整数费用，否则报错：`无法确定 xxx 的购买费用：包中未找到该卡牌定义。` 或 `卡牌 xxx 没有可用的费用字段。`
- 阵营确认规则与 `cardAdd` 相同。

### `cardDel <位置|卡牌类型>`

删除一张卡。

- 参数是纯数字时按槽位找；否则按卡牌类型找（同一类型有多张时只删最先找到的那张）。
- 删除后该槽位变空，可以再添加；删除不返还声望。

### `cardUnused <位置|卡牌类型>`

把一张已经用过的卡恢复为"未使用"状态。

- 只改 `used` 为 `false`
- 定位方式与 `cardDel` 相同：数字按槽位，否则按类型。

## 单位

单位（部队）数据在存档根目录的 `units.yml` 的单位。单位 id 从哪里来：
- `find <关键字>`：在当前 `units.yml` 里查；
- `refs` 打开的"战役部队列表.txt"：列出整个战役的单位 id、名称与初始类型，可以直接 Ctrl+F 搜索。
注意，units.yml文件在战役刚开始时可能不存在，其中单位数量也少于"战役部队列表.txt"。随战役推进，单位数据会逐渐加载到units.yml。

### `find <关键字>`

按关键字模糊查找单位，输出候选 id。

- 匹配范围：单位的本地化中文名、名称 id（`name_brief`）、单位类型名（`type`）；不区分大小写，子串匹配。
- 输出格式：

  ```text
  id=27    type=ger_inf_39     第 7 步兵师
  ```

### `select <id>`

选定一个单位，作为后续 `xp`、`str`、`type`、`spec`、`unspec` 的默认操作对象。

- 选中成功打印该单位的 id、名称、类型、活跃战力与经验，例如：

  ```text
  已选中单位 27: 第 7 步兵师 (type=ger_inf_39, act_st=5, xp=120)
  ```

### 省略单位 id 的规则

`xp`、`str`、`type`、`spec`、`unspec` 都支持两种写法，解析规则如下：

1. **没有选中单位**：第一个参数必须是单位 id。
2. **已经选中单位**：如果这次输入的总参数个数**不超过**该命令需要的"值"的个数，就把所有参数当作值，作用于选中单位。

各命令"值"的个数：

| 命令 | 值的个数 | 例（选中 27 后） |
| --- | --- | --- |
| `xp` | 1 | `xp 350` → 27 号的经验设为 350 |
| `str` | 2 | `str 5 1` → 27 号活跃 5、压制 1 |
| `type` | 1 | `type ger_inf_39` → 27 号类型改为 ger_inf_39 |
| `spec` | 1 | `spec engineer` → 给 27 号挂工兵 |
| `unspec` | 1 或 2 | `unspec engineer` → 移除 27 号的工兵；`unspec engineer 2` → 只移除 idx=2 的那条 |

```text
# 已选中 27 号，想改 6 号单位的战力：
> str 6 0
单位 27 战力: act_st=6 sup_st=0 合计=6      ← 错！改的是 27 号

> str 6 3 0
单位 6 战力: act_st=3 sup_st=0 合计=3       ← 正确，写满三个参数
```

`xp`、`type`、`spec`、`unspec` 写成"id + 值"时首参是数字，按 id 解释，不会误判。`str` 的压制可以省略，两参数形式会被优先当作对选中单位赋值，需要特别注意；`unspec` 选中后还支持 `<特种名> <idx>` 两参数形式（见该命令说明）。

### `xp [id] <值>`

设置单位经验值（0–399）。无校验，不要写入超过399的经验值，否则游戏会崩溃。

### `str [id] <活跃> [压制]`

设置单位战力（step）。单位的总战力 = 活跃战力（`act_st`）+ 被压制战力（`sup_st`）。

- 只写一个数时只改活跃战力，压制保持不变。
- 工具**不拦截**超限写入。实际上限为7，超出7游戏无法处理。可以超出部队类型的最大编制数量，不会有问题。

### `type [id] <类型>`

直接改单位的类型（`type` 字段），一次生效，不写绑定文件。

- 类型名必须真实存在（原版包中的单位类型，或你用 `create-type` 建的类型）。工具**不校验**类型是否存在，拼错时游戏读取该单位可能报错。
- 与 `bind` 的区别见下文 `bind`：`type` 只改这一次；`bind` 会记在绑定文件里，进入存档、`re`、`ql`、`reu` 时都会重新套用。想让改动在战役推进后仍然保持，用 `bind`。

### `spec [id] <特种名>`

给单位挂载一个特种（专家）。
- 最大特种数量上限3，无关编制。
- 同名特种可以重复挂载（例如两个工兵），每条各占一个槽位与 `idx`。

### `unspec [id] <特种名> [idx]`

移除单位上指定名称的特种。

- 同名有多条时只移除一条：不写 `idx` 时移除第一条（列表顺序，通常即 `idx` 最小者）；写 `idx` 时只移除该类型且 `idx` 相符的那一条。

### `set <id> <字段> <值>`

直接改单位的任意字段。

```text
> set 27 losses 0
单位 27.losses = 0
```

- 值先尝试按整数解析，解析失败就按字符串写入。因此 `set 27 type inf_02` 写字符串，`set 27 xp 399` 写整数。
- `set` 不接受选中上下文，第一个参数必须写单位 id。

## 自定义类型与绑定

这套命令用来"以原版单位为原型克隆一个新类型，再把某个单位指到这个新类型上"，从而在不改动画、模型的前提下定制数值与名称。

流程固定为两步：

1. `create-type` / `create-spec` 建出新类型实体（只创建，不影响任何单位）；
2. `bind <单位id> <类型名>` 把单位指过去。

两个步骤都是显式分离的，不会因为创建了类型就自动套到单位上。

### `create-type <原型> [新名] [--model-from <来源>]`

以原版单位类型为原型，在当前存档的临时 mod 中克隆一个新单位类型。

有用原版包路径：
`游戏安装目录\_packages\base\assets\surfaces\unit` 中存放单位的贴图（含DLC单位），查看以快速找到需要的模型。
`游戏安装目录\_packages\base\data\entity_types\unit_types` 中存放所有Unit的定义，同级目录下`specialists`存放专家部队的定义。文件名即为ID。

具体模型定义文件（.meta）从DLC包中搜索，默认从当前战役包中查找模型定义，其次是base包，使用其他DLC甚至Mod模型时需要使用来源参数，详见下文。

本工具主要自动化mod创建和模型查找，改单位属性直接改yml定义即可。使用 `refs temp` 命令打开临时mod，找到其中的单位yml配置，记事本打开。

- **原型**：原版单位类型名，即 `data/entity_types/unit_types/<名>.yml` 的主干（如 `ger_inf_39`）。
- **新名**：省略时自动取 `<原型>_custom`。
- **搜索原型的顺序**：配置里的额外搜索路径 → 当前战役对应的数据包（按存档的 `campaign_id` 映射）→ 基础包 `base`。类型、贴图目录、模型 meta 三者各自独立按此顺序取第一个存在的。
- **创建结果**写入 `<数据目录>/_packages/<存档名>_temp/` 下的三件套：
  - `data/entity_types/unit_types/<新名>.yml`
  - `assets/models/<新名>_meta.yml`
  - `assets/surfaces/unit/<新名>/`（贴图从原型复制）
- 原型若使用默认名称 id，会被改写成新实体的默认 id（`id_<新名>_brief`、`id_<新名>_full`）；原型若用自定义 id，则原样保留。
- 成功后打印创建位置，并输出 `提示：创建/修改 temp mod 实体后需重启游戏（重载 mod）才生效。` 与 `可用 bind <单位id> <类型名> 将单位指向该类型。`
- 同名实体已存在时，再次创建会覆盖 type 与 meta 文件；贴图目录只增不删。
- **模型本体不复制**，只复制 meta 描述。游戏仍须能加载来源包（通常是已安装的 DLC），否则模型会缺失。

`--model-from` 用来单独指定模型 meta 的来源。三种写法：

| 写法 | 含义 |
| --- | --- |
| `--model-from base` | 指定包名：`<原版包>/base/assets/models/<原型>_meta.yml` |
| `--model-from "C:/某路径/包目录"` | 指定包目录：按 `<目录>/assets/models/<原型>_meta.yml` 查找 |
| `--model-from "C:/某路径/xxx_meta.yml"` | 直接指定 meta 文件 |

- `-m` 是短形式，`--model-from=值` 的等号写法也支持。
- 路径含空格时用引号包起来。
- 不指定时沿用默认搜索顺序（当前战役包优先）。

示例：

```text
> create-type ger_inf_39 ger_inf_39_elite
原型定位成功: .../base/data/entity_types/unit_types/ger_inf_39.yml
模型 meta: .../base/assets/models/ger_inf_39_meta.yml
已创建单位类型实体: ger_inf_39_elite
位置: .../_packages/<存档名>_temp/data/entity_types/unit_types/ger_inf_39_elite.yml
提示：创建/修改 temp mod 实体后需重启游戏（重载 mod）才生效。
可用 bind <单位id> <类型名> 将单位指向该类型。
```

> 新建实体的类型数值与原型完全相同。要改攻击、防御、移动等数值，需要手工编辑生成的那个 type yml。

### `create-spec <原型> [新名]`

以原版特种为原型克隆一个新特种类型。

- 结构是"两件套"：`data/entity_types/specialists/<新名>.yml` 与 `assets/surfaces/specialist/<新名>/`，没有模型 meta。
- 默认新名同样为 `<原型>_custom`。

### `bind <id> <类型>`

把单位绑定到某个类型，并把绑定记录保存下来。

- 写入绑定文件 `<状态目录>/<存档名>/unit_type_modifier.yml`，内容为 `{单位id: 类型名}`；同时立刻把当前 `units.yml` 里该单位的 `type` 改成目标类型，打印 `单位 <id> type => <类型>`。
- 若该单位当前不在 `units.yml`（尚未上场、或战役还没进行到有它的场景），只记录绑定并打印 `已记录绑定: <id> => <类型>`，等它上场后自动应用。
- 绑定目标可以是自建类型，也可以是原版类型（多个单位共用一个类型是允许的）。

### `bindInfo`

列出当前所有绑定，每行显示单位 id、名称与目标类型：

```text
单位类型绑定：
  id=27    第 7 步兵师 -> ger_inf_39_elite
  id=31    (不在当前 units.yml) -> ger_inf_39_elite
```

### `rename <旧名> <新名>`

重命名临时 mod 中的实体（单位或特种）。

- 同步改三处文件名：type 文件、meta 文件（单位才有）、贴图目录。
- 若实体的名称 id 仍是默认形式 `id_<旧名>_brief` / `id_<旧名>_full`，同步改成新默认 id；自定义 id 保留不动。
- 绑定文件中引用旧名的记录改成新名，并逐条打印 `绑定已更新: 单位 <id> -> <新名>`。
- **注意**：改名不会迁移已经写过的翻译文本。原名下的中文仍挂在旧文本 id 上，改名后实体指向新 id，游戏里可能显示成 `id_新名_brief`。改名后需要再用 `brief` / `full` 写一次中文。

### `reu`

重新把绑定文件里的全部绑定应用到当前 `units.yml`，并打印改动数量。

```text
单位 27: type => ger_inf_39_elite
已应用 1 处绑定。
```

典型场景：战役，某时间节点后，游戏更新部队类型，在修改器里执行一次 `reu`，再 `save`。
进入存档、`re`、`ql` 时也会自动执行同样的应用（不打印细节）。

## 名称与文本

三条改名命令改动的位置不同，先看区别再选：

| 命令 | 改谁 | 写入位置 | 生效方式 |
| --- | --- | --- | --- |
| `troopName` | 单个单位 | `units.yml` 的 `name_brief` + 临时 mod 的本地化文件 | `save` 且重启游戏 |
| `brief` | 一个类型实体（单位或特种） | 实体 type 文件的 `name_brief` + 本地化文件 | 重启游戏 |
| `full` | 仅特种有该字段 | 实体 type 文件的 `name_full` + 本地化文件 | 重启游戏 |

本地化文件的位置：`<数据目录>/_packages/<存档名>_temp/localization/chi/<存档名>_strings.yml`。每个存档一个文件，互不影响。

### `troopName <id> <文本>`

只改**这一个单位**的显示名，不创建也不修改类型实体。

- 把该单位的 `name_brief` 改成 `<原名称id>_custom`（若尚未以 `_custom` 结尾），再把文本写进本地化文件。
- 文本可以含空格，多个词会被拼成一句；也可以用引号包裹。
- 打印两行，例如：

  ```text
  本地化写入: id_unit_27_brief_custom = 第 7 装甲师
  单位 27 名称设为: 第 7 装甲师 (id_unit_27_brief_custom)
  ```

- 同一单位再次改名会沿用同一个 `_custom` id，不会反复追加后缀。
- **生效需要两步**：`save`（把 `units.yml` 里的名称 id 写回存档）+ 重启游戏（让临时 mod 的本地化被加载）。

### `brief <实体名|单位id> <文本>`

改一个类型实体的简称（`name_brief`）。

- 参数是**实体名**时，直接改临时 mod 中该实体（单位或特种皆可）。
- 参数是**数字 id**时，改该单位所绑定实体。若该单位没有绑定，打印 `单位 <id> 没有绑定类型，先使用 bind。`
- 行为：把实体的 `name_brief` 指向默认文本 id `id_<实体名>_brief`，并把中文写进本地化文件。即使实体原本指向别的自定义 id，也会被重置为默认 id。

### `full <实体名|单位id> <文本>`

与 `brief` 相同，改的是全称（`name_full`），默认文本 id 为 `id_<实体名>_full`。

注意：**部队类型（unit_type）一般没有该字段**。

## 辅助命令

### `refs [目标]`

在资源管理器中打开某个目录。不带参数时打开参考列表目录。

| 目标 | 打开的目录 | 内容 |
| --- | --- | --- |
| `refs`（默认） | `<状态目录>/<存档名>/references/` | `战役部队列表.txt`、`战役总部列表.txt`、`卡牌列表/` |
| `refs uoc2` | `<数据目录>` | 存档与 `_packages`（状态目录见 `refs` 行） |
| `refs temp` | `<数据目录>/_packages/<存档名>_temp/` | 本存档的自定义实体与本地化文本 |
| `refs orig` | 原版包目录 | 游戏安装目录下的 `_packages` |

接受的别名：`ref`、`reference`（→ refs）；`appdata`、`.uoc2`（→ uoc2）；`mod`（→ temp）；`packages`、`original`（→ orig）。别名不区分大小写。

细节：

- 参考列表在**首次进入该存档**时生成。战役部队/总部列表取自存档的战役剧本，覆盖整个战役而非当前战斗，因此不随战斗推进变化。
- 卡牌列表按阵营分文件（如 `轴心国.txt`、`西方盟军.txt`、`苏联.txt`），每张卡列出类型名、中文标题、说明、费用、是否持久、是否含单位。卡牌定义来自原版包，与具体战役无关。
- 打开 `refs` 时，如果卡牌列表文件缺失会自动补生成；其余参考文件不会自动刷新。想整体重建，删除 `references` 目录后重新 `open` 该存档。
- 原版包路径未配置且未探测到时，`refs orig` 提示 `原版包目录未配置（config.yml 的 uoc2_orig_packages_path 为空且未探测到）。`
- 目标路径不存在时，参考列表提示 `参考列表尚未生成。`，其他目标提示 `<标签>不存在: <路径>`。

### `which`

显示当前会话涉及的四条路径，用来确认"我改的到底是哪个存档、文件在哪"：

```text
存档: blitzkrieg2
工作目录: <状态目录>/blitzkrieg2/work
临时 mod: .../.uoc2/_packages/blitzkrieg2_temp
绑定文件: <状态目录>/blitzkrieg2/unit_type_modifier.yml
```
