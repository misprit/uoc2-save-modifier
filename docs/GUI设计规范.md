## 1. 设计目标与验收判据

三条铁律。每条都必须能**当场检验**，否则不算数。

### 1.1 铁律一：傻瓜式

> 不读任何文档，也能完成"把某个单位的战力调到满并保存"。

| # | 判据 | 怎么验 |
|---|---|---|
| A1 | 核心操作 ≤ **3 步**：选存档 → 悬停滚轮 → 点「应用更改」 | 找个人看着做 |
| A2 | 任何灰掉的控件，**鼠标悬停都能看到原因** | 逐个禁用项试 |
| A3 | 任何写盘前，屏幕上一定先出现「要改什么」的逐条清单 | 点应用，看清单 |
| A4 | 不用记快捷键也能完成全部功能 | 禁用所有快捷键 |
| A5 | 破坏性操作（删除卡牌、下架商品）必须二次确认，且能撤销 | 逐个试 |

### 1.2 铁律二：好看

> 看起来像这款游戏的配套工具，而不是一个查表工具。

| # | 判据 | 怎么验 |
|---|---|---|
| B1 | 单位、特种兵、战区资产**全部用游戏原生贴图**，不自绘替代品 | 逐页看贴图来源 |
| B2 | 配色与静态查看器**同一套 PALETTE**，将来能拼成一个窗口 | 对照 `view_west_campaign.py` |
| B3 | 单位列表里**能看见头像和战力阶梯**，不是一列纯文字 | 看单位页 |
| B4 | 没有默认丑的 ttk 灰控件（Combobox / Scrollbar / Entry 全部改过皮肤） | 走查全页 |

### 1.3 铁律三：丝滑

> 调数值不需要"点进输入框 → 选中 → 输入 → 回车"。

| # | 判据 | 怎么验 |
|---|---|---|
| C1 | 鼠标悬停在**任意可改数值**上，滚轮即改，**无需先选中** | 试所有数值 |
| C2 | 改动 **200 ms 内可见**，不用点"预览" | 眼睛看 |
| C3 | 撤销是一步（按钮或 Ctrl+Z），且**能撤销一批改动**（不只一个） | 改 3 个再撤 |
| C4 | 任何耗时 > 300 ms 的操作有进度反馈 | 打开大存档 |
| C5 | 滚动 60 fps：列表不卡、不跳 | 上下滚 200 个单位 |

## 2. 信息架构

### 2.1 三层

```
┌─ L0 存档选择层 ──────────────────────────────────────────┐
│  启动即这一屏。列出所有存档，按最近修改倒序。             │
│  点一个 ⇒ 进 L1。                                        │
└──────────────────────────────────────────────────────────┘
                          ↓
┌─ L1 功能层（主窗口）──────────────────────────────────────┐
│  左侧 Rail：7 个功能页。右上：撤销 / 应用更改。           │
│  每个功能页里再分出 L2 对象层。                          │
└──────────────────────────────────────────────────────────┘
                          ↓
┌─ L2 对象层 ──────────────────────────────────────────────┐
│  单位详情 / 特种兵图鉴 / 商店条目 / 总部条目 / 卡牌条目   │
└──────────────────────────────────────────────────────────┘
```

### 2.2 为什么用左侧 Rail 而不是顶部标签页

**【决策】** 7 个功能页用**左侧竖排 Rail**（图标 + 中文名），不用 Notebook 标签。

理由：

1. 中文标签"战区资产""特种兵与兵库"太宽，7 个标签塞不下 1440 px；
2. Rail 每项有 **48 px 宽的状态位**，能显示"待应用 3 处"这类角标 —— 标签页放不下；
3. Rail 项可以**直接显示禁用原因**（灰 + 右侧小字"战斗中才可用"）；
4. Rail 可以**折叠成 56 px 图标条**，给单位列表让出空间；
5. 将来与静态查看器合并时，Rail 是可以左右拼接的（左看战役数据、右改存档）。

### 2.3 功能页清单

| # | 页 | 内容 | 能力位 | 备注 |
|---|---|---|---|---|
| 1 | 概览 | 存档体检、声望/分数、备份与撤销栈 | 恒可用 | |
| 2 | 单位 | 名册、战力、XP、特种兵挂载、改名 | `can_edit_units` | **主战场** |
| 3 | 特种兵 | 图鉴（378 种）、批量分配 | `can_edit_units` | |
| 4 | 总部 | 总部条目、兵库存量、CP | `can_edit_hqs` | |
| 5 | 卡牌 | 卡牌库存、会议手牌 | `can_edit_cards` / `can_edit_hand` | |
| 6 | 商店 | 按战线分组的商品、价格、数量 | `can_edit_store` | |
| 7 | 战区资产 | 11 类资产的可用次数 | `can_edit_theater_assets` | 只在战斗中 |

## 4. 视觉规范

### 4.1 调色板

**【决策】** 前 10 色**沿用静态查看器**的 `PALETTE`（`tools/view_west_campaign.py:22`），保证两个程序将来拼一起不打架；
后 6 色是本次新增，专供"可改 / 不可改 / 已改"的状态表达。

| token | 值 | 用途 |
|---|---|---|
| `window` | `#f4f6f8` | 窗口底 |
| `surface` | `#ffffff` | 卡片 / 面板底 |
| `surface_alt` | `#eef2f6` | 工具条 / 次级面 / 表头 |
| `border` | `#d4dbe3` | 分隔线 / 描边 |
| `text` | `#1f2933` | 正文 |
| `muted` | `#5c6b78` | 次要文字、禁用说明 |
| `accent` | `#245b8f` | 主色：选中、主按钮 |
| `accent_dark` | `#17456f` | 深主色：表头、标题 |
| `accent_light` | `#dceaf7` | 浅主色：提示条 |
| `selection` | `#cfe3f5` | 选中行底色 |
| **NEW** `ok` | `#1e6b3a` | 已满 / 成功 / 已应用 |
| **NEW** `ok_light` | `#e4f2ea` | 同上的浅底 |
| **NEW** `warn` | `#8a5a00` | 软警告 |
| **NEW** `warn_light` | `#fdf3e0` | 软警告浅底 |
| **NEW** `danger` | `#a4262c` | 破坏性操作（删除 / 下架 / 撤销） |
| **NEW** `danger_light` | `#fbe9ea` | 破坏性操作浅底 |
| **NEW** `stage_dark` | `#1b2430` | 头像衬底（深色底衬托透明贴图） |

**头像衬底为什么是深色**：游戏贴图是带 alpha 的士兵立绘，深底上的人物边缘才看得清（浅底上会发灰、糊成一团）。
列表里的头像一律放在 `#1b2430` 的圆角方块里，和游戏内兵牌观感一致。

### 4.2 字体

| 角色 | 字体 | 字号 | 说明 |
|---|---|---|---|
| 页面标题 | Segoe UI Bold | 16 | |
| 区块标题 | Segoe UI Bold | 11 | |
| 正文 | Segoe UI | 10 | |
| 次要 | Segoe UI | 9 | 禁用原因、提示 |
| **数值** | **Consolas** | 10–14 | **等宽**：滚轮变值时数字不左右跳 |

**【决策】** 所有"会被滚轮改的数值"一律用 Consolas 等宽。
普通比例字体在 `5 → 6 → 7` 之间宽度变化，滚动时整列会左右抖动 —— 这是"丝滑"最容易翻车的地方。

### 4.3 间距刻度

`4 · 8 · 12 · 16 · 24 · 32`（px）。任何内边距只能用这几个值。

### 4.4 控件皮肤

ttk 的默认控件（尤其 Combobox、Scrollbar、Entry）很丑，必须改：

| 控件 | 规格 |
|---|---|
| 表格（Treeview） | 行高 30，斑马纹 `#ffffff`/`#fafbfc`，选中 `selection`，悬停 `accent_light` |
| 表头 | `accent_dark` 底 + 白字 + `table_heading` 字体 |
| 滚动条 | `clam` 皮肤重绘：滑块 10 px 圆角、`borderwidth=0`、槽 `window` 色 |
| 输入框 | 白底 + 1px `border` + 聚焦时边框转 `accent` |
| 下拉框 | 同输入框；箭头区单独着色 |
| 主按钮 | `accent` 底白字；禁用时 `surface_alt` 底 `muted` 字 |
| 危险按钮 | `danger` 底白字（删除 / 下架） |
| 工具条 | `surface_alt` 底 + 上下 1px `border` |

### 4.5 圆角与阴影

Tk 没有真圆角。用**两层叠加**模拟：底层 `surface` 画 1px `border` 边框，顶层贴一张带 alpha 的圆角 PNG（运行时用 §10.2 的 PNG 管线生成，一次性烘成 9-patch 风格的小图，缓存复用）。
**不做**每控件独立阴影 —— 阴影只用在浮层（tooltip / 抽屉 / 对话框）。

### 5.2 特种兵 7 张图各是什么

### 5.3 单位头像：`sheet_L` 还是 `sheet_R`

**【实证】** 字节码 `uoc2/common/sheets/combat_sheet.pyc::_render_combat_sheet`：

```
进攻方：'unit/' + combat.att.type + '/sheet_L'
防守方：'unit/' + combat.dfe.type + '/sheet_R'
```

`uoc2/common/sheets/unit_sheet.pyc::_render_unit_sheet`（单位详情面板）**永远用 `sheet_L`**。

⇒ **【决策】** GUI 的单位列表、详情、图鉴**一律用 `sheet_L`**；
`sheet_R` 只在"对阵预览"这种要表现左右对峙的场景才用。

⚠️ **实测到的坑**：`unit/ger_pz_dlc7/` 里是 **`sheet_l.png`（小写 L）**，其余 628 个是 `sheet_L.png`。
⇒ **图标查找必须大小写不敏感**，否则德国虎式（Pz）类型的头像会凭空消失。

### 5.4 战力阶梯（step）语义

**【实证】** `uoc2/game_world/hq_ctrl.pyc::HQCtrl._fp_helper`：

```python
step_img = 'steps/step{}'.format('_' + equipment + '_' + equipment_q if equipment else '')
text    = locale.get(text_id).format(locale.get(name_brief), n)
#  text_id: equipment 为 None → id_n_steps_infantry
#          equipment_q == 1     → id_n_steps_mechanized
#          否则                  → id_n_steps_armor
```

中文模板：`id_n_steps_infantry = "{}步兵战力（{}）"` ⇒ 第二个 `{}` 就是**步数 n**。

**【实证】** `uoc2/state/entities/unit.pyc::UnitState.use_from_deploy`：

```python
num_steps = _type.max_st - self.tot_st          # 离满战力还差几步
if num_steps > 0:
    steps = min(部署来源给的步数上限, num_steps)
```

⇒ **单位到满战力还差几步 = `max_st − (act_st + sup_st)`**，`max_st` 来自类型表（不在存档里）。

**图标选择规则**（equipment / equipment_q 来自单位类型定义）：

| 条件 | 图标 |
|---|---|
| `equipment = null` | `steps/step.png` |
| `equipment = armor, equipment_q = 1` | `steps/step_armor_1.png` |
| `equipment = armor, equipment_q = 2` | `steps/step_armor_2.png` |
| `equipment = cavalry, equipment_q = 1` | `steps/step_cavalry_1.png` |
| `equipment = mountain, equipment_q = 1` | `steps/step_mountain_1.png` |
| `equipment = ski, equipment_q = 1` | `steps/step_ski_1.png` |
| 其它 / 找不到 | 兜底 `steps/step.png` |

**【实证】** base 包 627 个单位类型的 `(equipment, equipment_q)` 实际只出现三种：
`null/0`（398 个）、`armor/2`（135 个）、`armor/1`（94 个）。
⇒ 日常只会用到 `step.png` / `step_armor_1.png` / `step_armor_2.png` 三张；另三张留给 `cavalry` / `mountain` / `ski` 型总部兵库条目。

⚠️ **需要核心库补 2 个字段**：`UnitType` 目前**不暴露** `equipment` / `equipment_q`，
而 `movement` 已暴露。⇒ 见 §12 第 1 条（向后兼容的加字段，不动 8 个函数签名）。

### 5.5 战区资产 4 态变体

**【实证】** `theater/` 下 11 个资产，各 4 个变体：

`air_attack` · `air_attack_axis` · `air_attack_soviet` · `air_supply` · `flying_artillery` ·
`long_range_recon` · `naval_bombardment` · `naval_bombardment_axis` · `precision_bombing` ·
`saturation_strike` · `saturation_strike_axis`

每个有 `_neutral` / `_hover` / `_down` / `_disabled` 四态。

**【决策】** GUI 直接复用这套四态：默认 `_neutral`，鼠标悬停切 `_hover`，按下切 `_down`，
能力位不足时切 `_disabled`。
**这就是"好看"最省力的一招** —— 四态图游戏已经画好了，我们只管换文件名。

### 5.6 图标缺失怎么办

| 情况 | 表现 |
|---|---|
| 游戏目录没有 | 纯文字模式，图标位留 8px 空隙（不留灰块） |
| 某个类型没图（`specialist/generic`） | 显示"无图"占位（`border` 色圆角方块 + 首字母） |
| 类型表里有、贴图目录里没有（mod 新增类型） | 同上，**绝不因此拦住玩家改存档** |

⇒ 图标是**装饰**，不是数据。查不到图只能影响好看，不能影响能不能改。

## 6. 交互规范

**这是全文最重要的章节。** 用户的原始诉求"鼠标悬停在单位上，滚轮就能调节血量"就落在这里。

### 6.1 滚轮调值 —— 统一规则

所有**可改数值**用同一套行为，玩家只需要学一次。

| 修饰键 | 行为 | 适用 |
|---|---|---|
| 无 | **± 1** | 所有数值 |
| `Ctrl` | **± 10** | 大数（XP、声望、分数、价格、商店数量） |
| `Shift` | 直接到**边界**（最小 0 / 最大值） | 所有数值 |
| `Alt` | ± 1 但**跳过一个刻度**（用于 0.5 这类小数） | 预留 |

**完整反馈链**（一次滚轮 = 这一整套，缺一环就不算"丝滑"）：

1. **悬停高亮**（120 ms）：目标控件边框转 `accent`，底色转 `accent_light`；
2. **数值即时变**：不写盘，只改内存里的 pending 值；
3. **数值脉冲**（150 ms）：变化的数字短暂染 `accent` 色再淡回 —— 让眼睛抓住"哪里动了"；
4. **阶梯条同步**：战力段格条 / 阶梯图标跟着变；
5. **待应用计数 +1**：Header 的「应用更改」按钮上出现角标；
6. **不弹任何对话框**。

**边界处理**：

* 到达上限再往上滚：**数字闪一次 `warn` 色**，值不变（不静默、不循环、不跳变）；
* 往回滚回到原值：**该条待应用记录自动消失**（避免"改了又改回来"却还留在清单里）；
* 数值超出核心库允许范围（硬拦类，如 `xp > 400`）：**允许你先滚过去**，但在应用时会被 `plan.errors` 拦下并在清单上标红说明 —— 不在滚动时打断你。

**【决策】** 滚轮**绝不直接写盘**。所有改动先进"待应用"清单，一键提交。
理由：写盘要备份 + 校验 + 原子替换，滚轮一格就写一次会把磁盘写爆，也没法"撤销一批"。

### 6.2 悬停（hover）

| 目标 | 悬停表现 |
|---|---|
| 单位列表行 | 行底色转 `accent_light`；右侧滑出**快速条**（战力 −/+、XP −/+） |
| 单位头像 | 浮出**大图 tooltip**（原图等比缩到 240 px 宽） |
| 特种兵图标 | 浮出名称 + 攻防 / 装甲 / 火力 四项数值 |
| 战区资产图标 | 浮出资产名 + 当前可用次数 |
| 任何禁用控件 | 浮出**禁用原因**（来自 `caps.unavailable_reason(...)`） |
| 数值控件 | 浮出"滚轮可调"提示 + 当前值 + 上下限 |

**tooltip 规格**：深色底 `#1b2430`、白字、圆角 6px、延迟 400 ms 出现、跟随鼠标、
1.5 s 无移动后消失、右上角小箭头指向目标。

### 6.3 拖拽

| 拖什么 | 拖到哪 | 效果 |
|---|---|---|
| 战力段格条 | 段格条本身 | 拖到第 N 格 = 战力设为 N |
| 特种兵图标（图鉴里） | 单位行 / 单位详情 | 给该单位加这个特种兵 |
| 特种兵图标（单位身上） | 空白处 / 另一个单位 | 移除 / 转移 |
| 文件（备份列表里） | 文件管理器 | 打开备份所在目录 |

拖拽是**可选**的加速手段 —— 所有拖拽能做的事，都必须能用点击完成（A4 判据）。

### 6.4 确认流程（三道关）

```
   玩家改动
      │
      ▼
┌─────────────────┐
│ ① 待应用清单     │  右下抽屉，实时列出：对象 · 字段 · 旧值 → 新值
│   （随时可看）   │  软警告用黄色条插在对应行上方
└────────┬────────┘
         │ 点「应用更改」
         ▼
┌─────────────────┐
│ ② 确认对话框     │  列出将要被改动的**文件**（units.yml / store.yml …）
│                 │  列出改动条数、备份文件名
│                 │  [取消]              [应用更改]
└────────┬────────┘
         │ 核心库执行
         ▼
┌─────────────────┐
│ ③ 结果 Toast     │  ✓ 已保存 · 备份 xxx_BACKUP.usg   [撤销]
│                 │  ✗ 失败 · 原因一句话（原存档未改动）
└─────────────────┘
```

**【决策】** ②的对话框**必须列出文件名**，因为玩家要知道自己的存档里哪些文件被动了。
这与核心库 `Plan.changed_entries` / `FileChange.entry` 一一对应。

**软警告 vs 硬拦在 GUI 上的区别**：

| 核心库 | GUI 表现 |
|---|---|
| `plan.errors` | 确认框的「应用更改」按钮**禁用**，错误以红条列出，鼠标悬停给详细原因 |
| `plan.warnings` | 确认框顶部一条黄条"有 2 条软警告"，**仍可应用**，点开看详情 |

### 6.5 撤销

* 顶栏「↶ 撤销」按钮 + `Ctrl+Z`；
* 按钮上直接显示**人话摘要**：`撤销：单位 3 战力 5 → 7`（来自 `save.undo_peek()`）；
* 栈空时按钮禁用，悬停显示"没有可撤销的操作"；
* 撤销本身也走备份 + 校验管线（核心库已实现），失败要明确说"撤销栈基准已过期，拒绝执行"；
* 撤销栈深度显示在 Rail 底部（`撤销 2 条`）。

### 6.6 快捷键

| 键 | 作用 |
|---|---|
| `Ctrl+Z` | 撤销上一次提交 |
| `Ctrl+Enter` | 应用全部待应用改动 |
| `Ctrl+F` | 聚焦搜索框 |
| `Ctrl+A` | 全选当前列表 |
| `1`–`7` | 切换功能页 |
| `Esc` | 关闭弹层 / 取消选中 |
| `Delete` | 删除选中项（走二次确认） |
| `F5` | 重新读取存档 |

**【决策】** 快捷键是**加速器**，不是必需项；界面上每个快捷键都必须在菜单/提示里露出来。

### 6.7 禁用与原因

所有禁用态统一处理：

* 控件**置灰**（`muted` 字 + `surface_alt` 底）；
* **悬停必须有 tooltip 说明为什么**（`caps.unavailable_reason(feature)`）；
* Rail 上禁用的页，**仍然可以点进去** —— 看到的是"这个存档为什么没有这项"（而不是点了没反应）。
  例：独立场景存档没有商店 → 点进商店页看到一张说明卡 + 存档体检信息，而不是一片空白。

## 7. 各功能页设计

### 7.1 概览页

```
┌── 存档体检 ────────────────────┐  ┌── 战役进度 ─────────────┐
│ ✅ 单位    可改               │  │ 声望   [  1 240 ]  ◀▶   │
│ ✅ 特种兵  可改               │  │ 分数   [    87 ]  ◀▶   │
│ ✅ 总部    可改               │  │                        │
│ ⚠️ 卡牌    库存 12 张，可改   │  │ (滚轮可调 / 直接输入)   │
│ ❌ 战区资产 不在战斗中        │  └────────────────────────┘
└───────────────────────────────┘
┌── 备份与撤销栈 ──────────────────────────────────────────────┐
│ 备份   west_BACKUP.usg      10月4日 21:33   [打开目录]        │
│        west_BACKUP_2.usg    10月4日 21:30   [打开目录]        │
│ 撤销   ① 10月4日 21:33 单位 3 战力 5 → 7                    │
│        ② 10月4日 21:30 商店 3 件商品价格 -50%               │
└──────────────────────────────────────────────────────────────┘
```

* 「战役进度」只有声望 / 分数两个可改项（`Edit.progress`），数值大 → `Ctrl+滚轮 ±10` 更好使。
* 「存档体检」是**能力位矩阵的可视化**：8 个能力位各一行，绿勾/灰叉 + 一句人话。
  这张表同时也是**给玩家看的说明书** —— 让他知道这个存档能改什么、为什么。
* 备份列表由 `core` 的备份命名规则推断（`<名>_BACKUP.usg` / `_BACKUP_2`）。

### 7.2 单位页（主战场）

```
┌──────────────────────────────────────────────────────────────────────────────┐
│ [搜索单位/ID…]  [按总部 ▾] [只看满战力 ☐]              多选 3 个  [批量调整]   │
├───────────────────────────────────┬──────────────────────────────────────────┤
│ ▣ 西部线  第1装甲师      HQ 北部   │  ┌────────────────────────────────────┐  │
│   战力 ▓▓▓▓▓▒▒  5/7   XP 120      │  │  ▣  第1装甲师        (兵种：装甲)   │  │
│ ▣ 西部线  第2摩托化步兵  HQ 北部   │  │  us_arm_42      ✎ 改名              │  │
│   战力 ▓▓▓▓▓▓▓  7/7   XP 340  ★满 │  │  战力  5 / 7   ▲ 还差 2 步           │  │
│ ▣ 东部线  苏军近卫步兵   HQ 南部   │  │  阶梯 [step_armor_1.png] 2            │  │
│   战力 ▓▓▓▒▒▒▒  3/7   XP 40       │  │  活跃 4  压制 1  经验 120             │  │
│ ▣ 西部线  侦察骑兵       HQ 北部   │  │  特种兵  [图][图][＋添加]            │  │
│   战力 ▓▓▓▓▓▓▓  7/7   XP 210      │  └────────────────────────────────────┘  │
├───────────────────────────────────┴──────────────────────────────────────────┤
│ 待应用（2）                                                                    │
│   第1装甲师 · 战力 5 → 7                                       [撤销这一条]    │
│   侦察骑兵 · 改名 "改名后的名字"                                [撤销这一条]    │
│                                                        [ 丢弃全部 ] [ 应用更改 ]│
└──────────────────────────────────────────────────────────────────────────────┘
```

**单位行**的构成（左 → 右）：

| 元素 | 说明 |
|---|---|
| 头像 | 56×56 深底方块，内容是 `unit/<type>/sheet_L.png` 缩到 48×48 |
| 名称 | `name_brief`；玩家改过名就显示改后的 |
| 战力条 | **段格条**（不是进度条）：一格 = 1 点战力，填色 = 现有战力，空格 = 还能升几格 |
| 战力数值 | `4 / 7`（等宽字体）；满战力显示 `ok` 色 + ★ |
| XP | 灰色小字 |
| 状态标记 | 压制中 / 撤退 / 缺补给（用 `status/` 里的角标） |
| 待改标记 | 有待应用的改动 ⇒ 行右侧一个 `accent` 小圆点 + 名称变粗 |

**段格条（战力条）**：这是"血量条"，做成**离散格**而不是连续条 —— 因为战力的最小单位就是 1 点，
离散格能一眼看出"还差 2 格"。悬停时格与格之间出现细分隔。

**详情区**（右）分三块：

1. **抬头**：头像 + 名称（双击改名）+ 类型 id + 兵种；
2. **数值块**：战力（含阶梯图）、活跃/压制、经验 —— **每一项都能滚轮调**；
3. **特种兵块**：图标行 + `＋添加`（打开图鉴选择器）。

**改名**：双击名称进入编辑（Entry），`Enter` 提交，`Esc` 取消。
写入明文 `name_brief` / `name_full`（核心库已实现，**不走 temp mod / 本地化**）。

**批量调整**：多选（`Ctrl` 点选 / `Shift` 连选）后，顶部出现「批量调整」⇒ 弹出一个小面板，
选字段（战力 / XP / 经验 / 特种兵）+ 值 ⇒ 一次生成 N 条 `Edit`。

**单位列表的滚动**：单位多的存档有 200+ 行 ⇒ 列表必须**虚拟化**（只创建视口内的行）。
Tk 的 Treeview 本身够快（它就是虚拟的），但**自定义行控件**（要放头像）就得自己做虚拟化。
⇒ **【决策】** 单位列表**用 Canvas 自绘**（行高固定 64 px），不做 Treeview。
理由：头像 + 段格条 + 多个角标，Treeview 放不下（只能用文字），而"好看"要求必须能放图。

* 顶部显示**将改动哪些文件**（`units.yml` / `store.yml` …），
  方便玩家判断"这次写回影响大不大"；
* 底部：[丢弃全部] [应用更改]；
* 切换功能页时抽屉**不消失**（跨页攒改动是正常的）。

## 8. GUI ↔ 核心库调用时序

核心库 8 个函数在 GUI 里的用法（详见《核心库调用说明.md》）：

| GUI 动作 | 调用 | 要点 |
|---|---|---|
| 启动页填列表 | `list_saves()` | 只显示 `is_primary=True` 的，其余进"历史存档"组 |
| 打开存档 | `open_save(save_id)` | 失败抛 `FileNotFoundError` ⇒ 提示"存档已被移动或删除" |
| 切页 / 刷新 | `save.view(catalog=cat)` | `cat` 给 `max_st` / `max_spec`；**必须给**，否则战力上限显示不出来 |
| 算能力位 | `save.capabilities()` | `can_edit_*` 决定控件启用；`unavailable_reason()` 给 tooltip |
| 滚轮改值 | **不调核心库**，只改内存 pending | 核心库是**写盘**用的，不是"编辑态" |
| 点「应用更改」 | `save.plan_edit(edits, catalog=cat)` | `plan.ok == False` ⇒ 禁用确认框的「应用」 |
| 确认框 | `validate(plan)` | 第二道防线；失败同样禁用「应用」 |
| 确认后 | `save.commit(plan)` | 成功 ⇒ Toast + 备份路径；**失败必须说"原存档未改动"** |
| 写回后 | **重新 `save.view()`** | 提交会清缓存，不重读会显示旧数据 |
| 点「撤销」 | `save.undo()` | 按钮可用性看 `save.undo_available()`，文案看 `save.undo_peek()` |
| 下拉框数据 | `catalog.units()` / `spec_types()` / `card_types()` / `hq_types()` / `fronts()` | 只做**候选**，不���白名单 |
| 商店补全 | `catalog.store_defaults(campaign, front, conference)` | 只在"新增商品"时用 |

**统一原则（来自核心库规范，GUI 不得违背）**：

1. **GUI 永远不直接读写存档文件** —— 只经核心库；
2. **GUI 不自己判断"能不能改"** —— 只经 `capabilities`；
3. **GUI 不吞错误** —— 核心库返回的 `errors` 全部要显示，不能只弹一个"操作失败"；
4. **不往存档塞自定义字段**（`PREVENT_EXTRA`）；
5. 改完立刻重新 `view()`。

## 10. 技术实现

### 10.1 运行时：给随包 Python 补 tcl/tk

**【实证】** 随包的 `python/` 是 **embeddable 版 CPython 3.14.3，**没有** `tkinter`**
（`import tkinter` → `ModuleNotFoundError`）。要做原生窗口必须补齐。

补齐清单（**全部来自本机已有文件，不联网**）：

| 文件 | 来源 | 体积 | 作用 |
|---|---|---|---|
| `_tkinter.pyd` | 游戏 `lib\`（CPython 官方 3.14 构建） | 69 KB | C 扩展 |
| `tcl86t.dll` | 游戏 `lib\` | 1.84 MB | Tcl 8.6 运行时 |
| `tk86t.dll` | 游戏 `lib\` | 1.59 MB | Tk 8.6 运行时 |
| `zlib1.dll` | 游戏 `lib\` | 146 KB | **`tcl86t.dll` 的依赖，缺了 DLL 加载必失败** |
| `tkinter/`（含 `ttk.py`） | 系统 Python 3.14.7 的 `Lib\tkinter` 源码包 | ~250 KB | 纯 Python 层 |
| `tcl8.6/` | 游戏 `share\tcl8.6` | ~4 MB | Tcl 脚本库（`init.tcl` 等） |
| `tk8.6/` | 游戏 `share\tk8.6` | ~2 MB | Tk 脚本库（`tk.tcl` 等） |

合计 **+8.7 MB**（22.5 MB → 31.2 MB）。

**【实证】** 端到端验证通过（`docs/证据脚本/e144_tktest.py`）：

```
python: 3.14.3
  TkVersion const: 8.6 TclVersion const: 8.6
  Tk() OK  patchlevel: 8.6.15
  windowingsystem: win32
  themes: ('winnative', 'clam', 'alt', 'default', 'classic', 'vista', 'xpnative')
  clam OK
  PhotoImage OK
```

**注意事项**：

* 游戏的 `lib\tkinter` 是**冻结版**（只有 `__init__.pyc`，**没有 `ttk.py`**）⇒ 必须用系统 3.14.7 的**源码包**；
* `TCL_LIBRARY` / `TK_LIBRARY` 环境变量要在启动器里设（指向 `python\tcl8.6` / `python\tk8.6`），
  否则 Tcl 会去系统盘找 8.6 脚本库；
* `_tkinter.pyd` 依赖 `python314.dll` ⇒ 必须与随包 runtime 的 Python 次版本一致（3.14.x 补丁版 ABI 兼容，已验证）；
* `_tkinter.pyd` / `tcl86t.dll` / `tk86t.dll` 都是 CPython / Tcl / Tk 的官方组件，
  **可再分发**（PSF / BSD 风格许可）。

### 10.2 PNG 缩放管线（纯标准库）

**问题**：Tk 8.6 的 `PhotoImage` 能读 PNG（含 alpha）✅，但**只能整数倍 `subsample`**（最近邻，缩到 1/4 会糊成一团）❌。
随包 Python **没有 PIL**。

**方案**：写一个 ~250 行的纯标准库管线（`zlib` + `struct`）：

```
PNG 文件
  → 解码（IHDR/IDAT/PLTE、5 种滤波器反滤波）        ← 已验证可行
  → 缩放（双线性 + alpha 预乘，避免透明边缘发黑）
  → 重新编码 PNG（zlib 压缩 + CRC32）
  → PhotoImage(data=base64.b64encode(png))
```

**【决策】** 用**双线性 + alpha 预乘**（不是最近邻）：游戏立绘有大量半透明边缘，
最近邻缩放会出现锯齿和黑边。

**缓存**：LRU，键 = `(路径, 目标宽, 目标高)`，上限 **200 张 / 48 MB**。
同一张图常被列表和详情同时用（不同尺寸）⇒ 缓存命中率高。

**性能**：实测需控制在 **单张 < 80 ms**。列表滚动时按需解码，**只解码可见行**。

**兜底**：解码失败（未知色彩类型、损坏文件）⇒ 画一个 `border` 色圆角方块 + 类型首字母，**不崩**。

### 10.3 其它技术选型

| 议题 | 选择 | 理由 |
|---|---|---|
| GUI 框架 | **Tk 8.6 + ttk** | 与静态查看器同栈（PALETTE / 主题代码直接复用）；原生窗口 = 最傻瓜 |
| 主题 | `clam` + 自定义样式 | 静态查看器已验证可用 |
| DPI | `SetProcessDpiAwarenessContext(PER_MONITOR_AWARE_V2)` | 直接抄 `view_west_campaign.py:50` |
| 列表 | Canvas 自绘（单位页） / Treeview（其余页） | 单位行要塞头像和段格条，Treeview 放不下 |
| 虚拟化 | 自研（固定行高 + 视口裁剪） | 单位最多的存档 200+ 行 |
| 线程 | **单线程**；只有"读存档"放后台线程 + 队列回主线程 | Tk 不线程安全；读写存档 100 ms 级，先测再决定要不要线程 |
| 图标来源 | 运行时读游戏目录 | 180 MB 打包不现实；游戏是必需依赖 |
| 依赖 | **零第三方**（标准库 + PyYAML） | 与核心库一致；成品 zip 不用装 pip |

## 12. 需要你拍板的 4 件事

> 这 4 条我都能自己定，但它们会改变成品的样子或改动核心库，按规矩该你说了算。

### 12.1 核心库要加 2 个字段（唯一的核心库改动）

`UnitType` 目前不暴露 `equipment` / `equipment_q`，
而**战力阶梯图标的选择规则依赖这两个字段**（§5.4）。

* **选项 A（推荐）**：`UnitType` 增加 `equipment: str | None = None`、
  `equipment_q: int | None = None` —— **带默认值、向后兼容**，8 个函数签名不动，
  `test_api_contract.py` 不需要改。
* **选项 B**：不动核心库，GUI 自己再读一遍 `unit_types/*.yml` —— 能work，
  但把目录逻辑复制了一份，以后改类型表要改两处。

### 12.2 单位头像用 `sheet_L` 还是两阵营各用各的

游戏里 `sheet_L` = 进攻方朝向、`sheet_R` = 防守方朝向（§5.3）。
列表里没有"攻/防"之分。

* **选项 A（推荐）**：一律 `sheet_L`（和游戏单位详情面板一致）。
* **选项 B**：按单位的阵营分别用 L / R —— 语义不明（阵营 ≠ 攻守方），容易误导。

### 12.3 特种兵图鉴主图用哪张

`sheet_large.png` 只有 52×68（名字骗人），`hq_action_icon.png` 是 160×160（§5.2）。

* **选项 A（推荐）**：图鉴主图用 `hq_action_icon.png`（160×160），详情页小图用 `sheet_large.png`。
* **选项 B**：全部只用 `sheet_large.png` —— 统一，但图鉴会显得小气。

### 12.4 待应用清单：跨页攒，还是逐页清

* **选项 A（推荐）**：跨页攒（切页不清空），统一在右下抽屉里一次应用。
* **选项 B**：每个功能页各自一份清单，各自应用 —— 一次写盘只改一类东西，
  但要应用就得逐页点，容易漏。
