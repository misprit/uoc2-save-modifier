## 0. 三十秒上手

```python
from save_modifier_core import list_saves, open_save, Edit, validate

# 1) 列存档
for info in list_saves():
    print(info.save_id, info.display_name)

# 2) 打开
save = open_save("campaigns/west.usg")

# 3) 看当前状态（能力位驱动 GUI 的启用/禁用）
view = save.view(catalog=None)
if view.capabilities.can_edit_units:
    for u in view.units:
        print(u.id, u.display_name, u.xp)

# 4) 规划（不碰磁盘）
plan = save.plan_edit([Edit.unit_field(1, "xp", 300)])
if not plan.ok:
    print(plan.errors)
else:
    print(plan.notes)          # 人话："单位 1 的 xp：10 → 300"
    print(validate(plan).ok)   # 第二道防线

    # 5) 提交（备份 → 校验 → 原子替换，并压撤销栈）
    res = save.commit(plan)
    print(res.ok, res.backup)

    # 6) 不满意就撤（撤销前会校验基准，过期就拒绝）
    save.undo()
```

**核心库只依赖标准库 + PyYAML**，不 import tkinter、不启子进程、不碰游戏进程。

## 2. 8 个对外函数（§0.2 冻结版）

### 2.1 `list_saves(paths=None, *, include_archived=True) -> list[SaveInfo]`

扫描 `%LOCALAPPDATA%\.uoc2\save\{campaigns,games,Old Saves}`，按最后修改时间**倒序**返回。

```python
@dataclass(frozen=True)
class SaveInfo:
    save_id: str          # 相对存档根目录的 posix 路径，如 "campaigns/west.usg"
    path: Path            # 绝对路径
    kind: str             # "campaign" | "standalone"
    archived: bool        # 在游戏的「Old Saves」里？
    is_primary: bool      # 是"当前存档"吗（备份/副本为 False）
    campaign_id: str | None
    scenario: str | None          # 当前战斗的场景 id
    standalone_scenario: str | None
    mtime: float
    size: int
    # 派生属性
    name: str             # 不含扩展名的文件名
    display_name: str     # 给玩家看的名字（已含"战役 ·"/"独立场景 ·"标注）
    is_standalone: bool
```

> **GUI 提示**：只显示 `is_primary=True` 的；备份/副本单独列一组。

### 2.2 `open_save(save_id, paths=None) -> Save`

`save_id` 用 `list_saves()` 给的 `save_id`（或直接给绝对路径）。
找不到会抛 `FileNotFoundError`。

```python
with open_save(info.save_id) as save:      # 记得 close（with 最省心）
    ...
```

### 2.3 `save.view(catalog=None) -> View`

给 GUI 用的**只读投影**。`catalog` 给了才会填 `max_st` / `max_spec`
（战力上限在**类型定义**里，不在存档里 —— §5.3）。

```python
@dataclass
class View:
    save: SaveInfo
    capabilities: Capabilities   # 8 个能力位（见 §3）
    stage: str                   # 显示文本：战斗中（第 N 回合）/ 会议界面（已发牌）/ …
    prestige: int | None
    score: int | None
    units: list[UnitView]
    hqs: list[HqView]
    cards: list[CardView]        # 根 cards.yml
    hand: list[CardView]         # 当前会议发到手里的牌
    store: list[StoreEntryView]
    battle_turn: int | None
    warnings: list[str]          # 该存档的注意事项，直接显示给玩家
```

各条目的字段：

```python
UnitView:  id, type, name_brief, name_full, hq_id, xp, act_st, sup_st,
           specs: tuple[dict,...], uv, entr, supply, ap, losses, retreated,
           in_roster: bool, max_st: int|None, max_spec: int|None
           # 派生：total_st（活跃+压制）、display_name
HqView:    id, name_brief, name_full, general, force_pool: tuple[dict,...],
           cp, max_cp, supply, uv, xp, xp_target, branch_levels,
           persistent, overrun, turn_disbanded
           # 派生：display_name
CardView:  card_type, is_free, position, unit_id, used
StoreEntryView: front, equipment, spec, nationality, price, quantity
           # 派生：what（= spec 或 equipment）
```

> ⚠️ `view.stage` **只用于显示**，**不得**用来决定改哪张表 —— 那是能力位的活。

### 2.4 `save.plan_edit(edits, catalog=None) -> Plan`

**不碰磁盘。** `edits` 是一组 `Edit`（结构化，**不接受 YAML 文本**）。

```python
@dataclass
class Plan:
    save_id: str
    path: Path
    changes: list[FileChange]     # 每个被改条目
    notes: list[str]              # 一行行的人话说明（GUI 主视图用这个）
    errors: list[str]
    warnings: list[str]
    ok: bool                      # = not errors
    changed_entries: list[str]
    summary: str

@dataclass
class FileChange:
    entry: str        # ZIP 内条目名，如 "units.yml"
    layer: str        # "L1" 或 "L3"（L3 只可能是战区资产那一个例外）
    before: str
    after: str
    diff: str         # unified diff
    notes: list[str]
    is_l3_exception: bool
```

**`plan.ok` 为假就绝对不能提交**（`plan.errors` 里有原因）。

### 2.5 `validate(plan) -> ValidationResult`

对计划做**第二遍独立复核**（规划时已经查过一遍，这里再查一次，防止任何路径绕过校验）。

```python
@dataclass
class ValidationResult:
    ok: bool
    errors: list[str]
    warnings: list[str]
    summary: str
```

### 2.6 `save.commit(plan) -> CommitResult`

写回。顺序**固定**，一步都不能省：

1. **备份** —— `<存档名>_BACKUP.usg`（同名已存在就 `_BACKUP_2`…，**绝不覆盖**）
2. **写临时文件** —— 按原存档的条目清单与顺序重建，元数据沿用原存档
3. **校验** —— 逐条 SHA256 比对，确认**只有计划里那几个条目变了**
4. **原子替换** —— `os.replace`

任何一步失败都**完整回滚**：原存档一个字节都不动。
成功后还会把本次改动**压进撤销栈**。

```python
@dataclass
class CommitResult:
    ok: bool
    nothing_to_do: bool     # 计划里没东西可改（不是错误）
    path: Path | None
    backup: Path | None
    changed: list[str]      # 实际变了的条目
    errors: list[str]
    warnings: list[str]
    report: PackReport | None
    summary: str
```

### 2.7 `save.undo() -> UndoResult`

修改器**自己的**撤销栈（与游戏内「重置会议」是两套独立机制）。

* 粒度 = **一次 commit**（一次改了 3 个单位就一起撤）
* 栈**落盘**在存档旁边的 `<存档名>.undo.json`（游戏只扫 `*.usg`，不冲突）
* 撤销前**重新校验基准**：当前内容必须等于记录里的"改后哈希"；
  对不上（多半是玩家在游戏里手动改过）⇒ **拒绝执行并说明原因**，不硬改
* 撤销走的是**和 commit 完全相同**的写回管线（也会再生成一份备份）

```python
@dataclass
class UndoResult:
    ok: bool
    nothing_to_do: bool     # 栈是空的
    path: Path | None
    backup: Path | None
    restored: list[str]
    errors: list[str]
    warnings: list[str]
    summary: str
```

辅助（8 个函数之外，但 GUI 需要它们决定按钮是否可点）：

```python
save.undo_available() -> bool     # 栈里有没有东西可撤
save.undo_peek() -> str | None    # "可撤销：改了 1 个文件：单位 1 的 xp：314 → 77"
```

### 2.8 `catalog.*` —— 下拉框数据源

**只做候选，绝不做白名单**（§9.1.3）。

```python
from save_modifier_core import catalog

catalog.units()        # list[str]  627 个单位类型
catalog.hq_types()     # list[str]  213 个总部类型
catalog.card_types()   # list[str]  39 个卡牌类型
catalog.spec_types()   # list[str]  375 个特种兵类型
catalog.fronts(campaign_id) -> list[str]   # 某战役包的战线名
catalog.store_defaults(campaign_id, front, conference) -> list[dict]
```

也可以直接用 `Catalog` 类（要拿 `max_st` / `spec_cap` 时用这个）：

```python
cat = Catalog(CorePaths.discover())
cat.max_st("us_inf_42")      # 6
cat.spec_cap("ger_inf_39")   # 2 = min(3, max_spec)
cat.step_icon("us_arm_42")   # "step_armor_2"  ← 战力阶梯图标名
```

#### `UnitType` 的字段（2026-11-18 扩充）

| 字段 | 类型 | 说明 |
|---|---|---|
| `name` | `str` | 类型名 |
| `faction` / `nationality` | `str \| None` | 阵营 / 国籍 |
| `movement` | `str \| None` | `infantry` / `mobile` / `cavalry` / `mountain` |
| `attack` / `defense` / `armor` | `int \| None` | 基础属性 |
| **`max_st`** | `int \| None` | **战力上限**（上限在类型定义里，不在存档里） |
| `max_spec` | `int \| None` | 特种兵上限；`None` = 该类型没这个字段 |
| **`equipment`** | `str \| None` | **装备类别**（`None` = 无装备） |
| **`equipment_q`** | `int \| None` | **装备档位**（0 = 无装备） |
| `name_brief` | `str \| None` | 本地化 id |
| `spec_cap` | `int`（属性） | `min(3, max_spec or 3)` |
| **`step_icon()`** | `str`（方法） | **战力阶梯图标文件名**（不含目录与扩展名） |

**`step_icon()` 的规则**（游戏自己的 `hq_ctrl.pyc::HQCtrl._fp_helper` 字节码实证）：

```python
'steps/step{}'.format('_' + equipment + '_' + equipment_q if equipment else '')
```

| 类型 | `equipment` / `equipment_q` | `step_icon()` |
|---|---|---|
| `us_inf_42` | `None` / `0` | `"step"` |
| `us_arm_42` | `armor` / `2` | `"step_armor_2"` |
| `ger_pz_dlc7` | `armor` / `2` | `"step_armor_2"` |

⇒ GUI 拿 `cat.step_icon(type)` 拼成 `assets/surfaces/steps/<名字>.png` 即可。
**先判 `equipment` 真假，再拼 `equipment_q`** —— 游戏就是这么拼的（`equipment` 为 null 时 `equipment_q` 恒为 0，
不会拼出 `step__0`）。

> 实测：base 包 627 个单位类型的 `(equipment, equipment_q)` 只有三种组合 ——
> `(None, 0)` 398 个、`(armor, 2)` 135 个、`(armor, 1)` 94 个。

## 3. 能力位（§3.4.5）—— GUI 的启用/禁用全看它

**按能力位开关，不按状态分支。** 缺哪个文件就禁掉对应功能。

```python
caps = save.capabilities()
caps.has_root_units     # 根 units.yml 存在？→ 单位功能
caps.has_root_hqs       # 根 hqs.yml 存在？  → 总部 / 兵库功能
caps.has_root_cards     # 根 cards.yml 存在？→ 卡牌功能
caps.has_root_store     # 根 store.yml 存在？→ 商店功能
caps.has_card_store     # 当前停在会议界面（已发牌）？
caps.cp_conference      # 有会议检查点（只读）
caps.cp_game            # 有战斗检查点（只读）
caps.in_battle          # 当前在战斗里？→ 战区资产功能

# 派生（写代码时用这些）
caps.can_edit_progress      # 恒为 True
caps.can_edit_units
caps.can_edit_hqs
caps.can_edit_force_pool
caps.can_edit_cards
caps.can_edit_store
caps.can_edit_hand
caps.can_restore_hand       # 有会议检查点就能恢复牌局
caps.can_edit_theater_assets  # = in_battle
caps.can_undo_in_game

# 禁用时给玩家看的原因（直接显示）
caps.unavailable_reason("units")   # "该存档还没有可编辑的单位（战役开局尚未生成名册）"
```

> 实测 70 个存档：根 `units.yml` 67/70、`cards.yml` 63/70、`store.yml` 67/70、
> `hqs.yml` 70/70。独立场景存档 3/3 **没有商店也没有卡牌** —— 这两块整个禁用。

## 4. `Edit` —— 11 种编辑

```python
from save_modifier_core import Edit

Edit.progress(field, value)                 # field: "prestige" | "score"
Edit.unit_field(unit_id, field, value)      # xp / act_st / sup_st / name_brief / name_full / uv / entr / supply / ap
Edit.unit_spec_add(unit_id, spec_type)      # 特种兵类型必须在 375 个 specialists 里
Edit.unit_spec_remove(unit_id, spec_type, idx=None)
Edit.hq_force_pool(hq_id, index, quantity)  # 总部兵库第 index 条的存量
Edit.card_add(card_type, *, is_free=False, position=None, unit_id=None)
Edit.card_remove(position)
Edit.store_set(front, index, field, value)  # field: "price" | "quantity"
Edit.store_remove(front, index)             # 下架 = 删条目（quantity=0 是非法值）
Edit.hand_restore()                         # 恢复上次会议的牌局（读 L2 → 写 L1）
Edit.theater_asset(asset, *, to_use, uses_total=None, uses_turn=0)
```

**明确不支持**（会报错，不是静默忽略）：

| 想做的事 | 结果 |
|---|---|
| `Edit.unit_field(id, "type", ...)` 改编制 | 报错并给替代建议（改战力 / 特种兵） |
| 新增单位 / 新增单位类型 | **没有这种 Edit** —— 要写只读层，游戏内回退不掉 |
| 改登陆进场特种兵 | **没有这种 Edit** |
| 跳到某会议 | **没有这种 Edit** |
| 改 `milestones` | **没有这种 Edit** —— 改了也是"改了却像没改" |

### 4.1 软警告 vs 硬拦

| 情况 | 行为 |
|---|---|
| 能力位不满足 | **硬拦**（`plan.errors`） |
| 值越界（xp > 400 等） | **硬拦** |
| 战力超过类型的 `max_st` | **软警告**（`plan.warnings`），照写 |
| 特种兵类型不存在 | **硬拦** |
| 特种兵数量超过 `min(3, max_spec)` | **硬拦** |
| 商店 `quantity` 设成 0 | **硬拦**（游戏没有售罄标记，下架要删条目） |
| 改的是战斗外会被重算的字段（`uv`/`entr`/`supply`/`ap`） | **软警告** |

## 5. GUI 的标准五步

```
1. list_saves()            → 填存档下拉框（只列 is_primary）
2. open_save(id)           → 拿到 Save
3. save.view(catalog)      → 填表格；用 capabilities 决定哪些按钮可点
4. save.plan_edit(edits)   → 填变更清单（plan.notes）+ diff 面板
   ├─ plan.ok == False     → 显示 plan.errors，不给"保存"按钮
   └─ validate(plan)       → 第二道防线
5. save.commit(plan)       → 成功提示 + 备份路径；之后"撤销"按钮变可用
   └─ 玩家点撤销 → save.undo()
```

**写回后一定要重新 `save.view()`** —— 提交会清掉内部缓存的解析结果。

## 6. 保真保证（可以拿去跟玩家承诺）

| 保证 | 实测 |
|---|---|
| 写回时**没改的条目**逐条 SHA256 一致 | 70 存档 / 52356 条目全量回归 |
| 写回时**改过的那一个文件内部**，没改的行也不动 | L1 条目往返 **337/337 字节一致** |
| 备份是原文件的**字节拷贝**（不是重打包的产物） | `backup_matches_original()` |
| YAML 风格与游戏**完全一致**（含中文转义成 `\uXXXX`） | 复刻游戏自己的 `_Dumper`（字节码实证） |
| 条目顺序、时间戳、`external_attr` 沿用原存档 | `packing.repack_overlay()` |

**写入范围**：只写 L1（根目录 5 个 YAML），加上**唯一的 L3 例外** ——
当前进行中战斗的 `theater_assets`。检查点 / 回合历史 / 战役文档**只读**。
**绝不新建文件**（`PREVENT_EXTRA`）。

## 7. 错误处理约定

| 情况 | 表现 |
|---|---|
| 能力位不足 | `plan.errors` 里有中文原因（`caps.unavailable_reason`） |
| 值非法 | `plan.errors`（**不写盘**） |
| 存档在规划之后被别人改过 | `commit` 报错拒绝写入（别把人家的改动覆盖掉） |
| 写回中途失败 | 原存档一个字节都不动（临时文件丢弃） |
| 撤销基准过期 | `undo` 报错，**拒绝执行**，并提示可以复制 `_BACKUP.usg` 回退 |
| 撤销栈文件损坏 | `undo` 报错并说明（**不静默吞掉**） |

**核心库不抛"业务异常"** —— 校验类问题全部走 `errors` 列表；
只有真正unexpected的情况（文件不存在、存档损坏）才抛异常。

## 8. 已知边界

* **独立场景存档没有商店、没有卡牌** —— 能力位会把这块整个禁用。
* **战区资产只能在战斗里改** —— 战斗外改会被场景重算覆盖（这是"改了却像没改"）。
* **改名直接写明文**（写进 `name_brief` / `name_full`）—— 不写 temp mod，不写本地化包。
  游戏会正常显示。
* **`type`（编制）不可改**。
* 撤销栈上限 20 条 / 32 MB，超了从最旧的开始丢。
* 撤销栈文件是 `<存档名>.undo.json`，**和存档放在一起** —— 玩家备份存档目录时记得一起带上。
